# WarrantyVault 🛡️

**Digital Warranty & Receipt Management System** — A clean, humanized full-stack web application for tracking product warranties, uploading receipts, running OCR, and recording repair history. Built with vanilla HTML5, CSS3, and JavaScript on the frontend, with an Express and MongoDB backend.

> **College Docker project submission — mid-November 2026**

---

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | Vanilla HTML5 + Custom CSS3 + Pure JavaScript (ES6+, No React, No Build Tools) |
| Backend | Node.js 24 LTS + Express 4 + Mongoose 8 + Zod |
| Database | MongoDB 7 (Docker persistent volume) |
| Auth | JWT via HttpOnly cookie + bcryptjs |
| OCR | Tesseract.js (raster image receipts) |
| Infrastructure | Docker + Docker Compose + Nginx |
| Testing | Jest (44 automated backend test cases) |

---

## Why Vanilla HTML/CSS/JS? (Humanized Design)

Instead of relying on heavy frontend frameworks (React, Vite, Tailwind, Redux), the frontend is written cleanly and authentically using standard web technologies:
- **Zero build step**: Edit `index.html`, `style.css`, or `app.js` and refresh your browser immediately.
- **Readable & maintainable**: Understandable DOM manipulation, native `fetch` requests, and straightforward hash-based routing (`#/dashboard`, `#/products`, `#/login`).
- **Lightweight & fast**: No bloated `node_modules` on the frontend, fast load times, and minimal memory usage.
- **Authentic**: Looks and behaves like code genuinely built by a student rather than autogenerated AI boilerplate.

## Quick Start

### Prerequisites
- **Docker Desktop** installed and running (or local Node.js + MongoDB)
- Git

### 1. Clone and Configure

```bash
git clone <your-repo-url>
cd WarrantyVault
cp .env.example .env
```

**Edit `.env` and set `JWT_SECRET` to a secure string:**
```bash
# Generate a secure secret:
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

### 2. Start with Docker Compose

```bash
docker compose up --build
```

This starts:
- **MongoDB** on internal Docker network (port 27017, internal only)
- **Backend API** on internal Docker network (port 5000, internal only)
- **Frontend + Nginx** on **http://localhost:8080** (your browser)

Wait for all services to be healthy (~30-60 seconds on first build).

### 3. Open App

Visit **http://localhost:8080** — register a new account and start adding products.

### Stop and Restart (without losing data)

```bash
# Stop containers (data is preserved in Docker volumes)
docker compose down

# Restart and rebuild
docker compose up --build
```

> ⚠️ **Never run `docker compose down -v`** — this deletes all your data volumes!

## Development Mode (without Docker)

### Prerequisites
- Node.js 18+ 
- MongoDB running locally on port 27017

### Run Backend & Frontend Together

Because the backend directly serves the static frontend files:

```bash
cd backend
npm install
# Ensure .env has MONGO_URI=mongodb://localhost:27017/warrantyvault
node src/server.js
```

Now open **http://localhost:5000** in your browser! Both the API and frontend will be running.

## Environment Variables

Copy `.env.example` to `.env` and fill in values:

| Variable | Required | Description |
|---|---|---|
| `JWT_SECRET` | **Required** | At least 32 random characters. |
| `MONGO_URI` | Required | MongoDB connection string. In Docker: `mongodb://mongo:27017/warrantyvault` |
| `NODE_ENV` | Optional | `development` or `production` |
| `PORT` | Optional | Backend port (default: 5000) |
| `COOKIE_SECURE` | Optional | `true` for HTTPS deployments |
| `MAX_FILE_SIZE` | Optional | Max upload size in bytes (default: 5242880 = 5MB) |
| `UPLOAD_DIR` | Optional | Upload directory path inside container |
| `CORS_ORIGIN` | Optional | Allowed origin for CORS |

## Architecture

```
Browser
  │
  └─► Nginx (port 8080 → 80)
        ├─ Serves static HTML/CSS/JS files
        └─ Reverse proxies /api/* → backend:5000
                                        │
                                        ├─► Express API
                                        │     ├─ JWT auth (HttpOnly cookie)
                                        │     ├─ Mongoose models
                                        │     ├─ Multer file uploads
                                        │     └─ Tesseract.js OCR
                                        │
                                        └─► MongoDB (mongo_data volume)
                                              Receipts (receipt_uploads volume)
```

## Features

### ✅ Implemented Core Features
- User registration and login with secure JWT HttpOnly cookies
- Product CRUD with validation (name, brand, model, category, purchase date, duration, price, serial number, seller, notes)
- Automatic warranty expiry date calculation (calendar months, end-of-month clamping)
- Warranty status: Active / Expiring (≤30 days) / Expired
- Live search by name/brand, filter by category/status, sort by expiry
- Secure receipt upload (JPEG, PNG, WEBP, PDF - max 5 MB)
- Authenticated receipt download (files never publicly accessible)
- Tesseract.js image OCR with editable review step
- Service/repair history CRUD (date, service center, cost, description, status)
- Live dashboard with real MongoDB data
- In-app reminders for 30/15/7 days before expiry
- Clean responsive layout for desktop and mobile screens
- Docker Compose deployment with persistent volumes (data survives container restarts)
